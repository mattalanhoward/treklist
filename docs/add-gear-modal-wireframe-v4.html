  • 1Search unchanged. Same box, same AI camera scan. Typing filters; clearing it returns to browse (Frame 2), where a mode carousel advertises what the box accepts: product name, store URL, Decathlon item ID, photo scan.
  • 2Facet row, designed in for 7× scale. Active category chip + that category’s subcategory chips (locked taxonomy; deepest is 12 subs — the row scrolls). Brand ships here later without re-layout.
  • 3Enriched rows carry the decision. Brand once (eyebrow), name, thumbnail, and the hero number — weight — in every row. Most adds should end here without the pane.
  • 4Click = preview, checkbox = add. Row click focuses the pane; only the checkbox batches. No stacked modal — “Full details” is a link inside the pane for the rare deep-dive.
  • 5Weight is the pane’s hero, with the precision disclosure directly beneath it (flat-across-variants, per-single-unit, verified date). Renders in the user’s global g / oz preference, region-defaulted.
  • 6Variants live in both places, and never block the batch. Row quick-pick for “I know my size”; pane holds the full picker; one synced state. Checking without picking adds the default fit and flags the gear item “size not set” — honest, editable later, zero friction now.
  • 7Virtualized list. Long result sets render windowed; the footer row signals more without pagination chrome.
  • 8Batch commit names its destination. “Add 2 to Hiking” from a list category, “Add 2 to My Gear” from the locker — the count and target are never a leap of faith. Disabled at zero.
  • 9Report an issue. Quiet flag under the specs it disputes (also in the mobile sheet). Opens the popover in Frame 6 — never a stacked modal. Reports auto-attach item, variant, and the values shown.
  • 10Added ≠ locked. Items already in My Gear or on this list stay checkable — checking adds them to this list (or another copy). The list’s quantity stepper covers same-category duplicates; this covers the “same item, two categories” case that used to be blocked.
  • 11Custom is never far. The last row of every result set creates a custom item seeded with the query — zero results makes it the loudest thing on screen. Opens the Custom tab pre-filled. (v2 candidate: merge the tabs into one search-first surface.)

  • 12Full-screen takeover on mobile — and a history entry. Same contracts as desktop, laid vertically. Opening it pushes state, opening the sheet pushes again: Android back / iOS swipe-back closes the sheet first, then the takeover — never the whole app. This is the #1 mobile-browser trust signal.
  • 13Sticky commit bar replaces the desktop footer. Appears with the first checkbox, always names count + destination, stays put while the list scrolls under it. Sits above env(safe-area-inset-bottom); container is 100dvh (never 100vh); the bar hides while the keyboard is open so it can’t float mid-screen.
  • 14The sheet is mobile’s preview pane. Weight hero + precision disclosure, two key specs, fit-variant chips, destination-named add. Tap row text = sheet; checkbox = batch without the sheet, using the default-fit / “size not set” rule (marker 6). Dismiss by swipe-down, scrim tap, or back gesture.
  • 15Tap-target contract. Rows ≥ 56 px tall; the checkbox draws at 22 px but the whole leading zone is a 44×44 hit area; size chips ≥ 40 px wide. Search input font-size is 16 px — anything smaller makes iOS Safari auto-zoom on focus, the single most common “feels broken in the mobile browser” bug.
  • 16Rotating placeholder, not mode chips, on mobile. The “name / store URL / Decathlon ID” hint cycles inside the empty search field (Amazon/Airbnb pattern). Chips under the box read as filters and would collide visually with the facet chips; desktop keeps the labelled “Search by:” row because it has room to label it.
  • 17After the add, don’t eject the user. Sheet-add keeps them in the list — sheet closes, row flips to “In list ✓”, quiet toast. Batch commit closes the takeover with an “Added 2 to Hiking — Undo” toast. Undo beats a confirm dialog for both newbies and power users.

Server side: dedupe by item + field with a counter → queue in the admin catalog view. Crowd-sourced QA for the 7× expansion.
Entry points — one component, two modes: category “Add item” · sidebar add · My Gear add (all = add mode, batch, destination-echo commit) · Swap item = the same surface in single-select mode: checkboxes hidden, row tap previews as usual, pane/sheet button reads “Swap for this” and replaces the source item (keeps category, quantity, worn/consumable flags where compatible). Never a separate build.
Item Details modal stays separate (edit-my-instance job: weight override, variant, delete; read-only on public lists) — but adopts this spec’s weight hero + precision disclosure and gains the ⚑ report flag.
Variant-on-batch — CONFIRMED 2026-07-12: checking a variant row without picking adds the default fit and flags the gear item “size not set”; never blocks the batch.
“Request a gear item” — CUT (2026-07-12): the inline custom-create row covers the user need with zero curation burden. Replacement demand signal: zero-result searches are silently logged (query · count · last seen) to a table in the admin view — catalog-gap intel without a fulfillment promise.
Locked decisions (expensive to change later): click = preview / checkbox = add · row data contract = weight + one key spec + thumb · facet row present from day one · virtualized list · Added never locks a row · variant default = fit default + “size not set” flag · commit button names count + destination.
Cheap to adjust later: modal width vs full-height drawer · hover-preview enhancement · chip styling · pane content arrangement · featured-brand slot contents · merging Import/Custom tabs (v2 candidate).
Mobile build contract (the “better in the browser than competitors” claims live or die here): 16px input font (kills iOS focus-zoom) · 100dvh + env(safe-area-inset-bottom) · takeover + sheet are history entries (back gesture never exits the app) · commit bar hides under keyboard · toast + Undo after every add, never a confirm dialog · virtualized rows on mobile too.
